# 开发计划书

> 本文定义 M0–M9 十个里程碑。每个里程碑都有明确的**交付物**、**涉及文件**、**验收用例**和**完成定义**。
> 进度状态不写在这里，写在 [PROGRESS.md](PROGRESS.md)。本文只定义「要做什么」，PROGRESS 记录「做到哪了」。

## 总体策略：垂直切片优先

不采用「先把 8 个职业全写完再做渲染」的水平铺开，而是**先打通一条端到端的窄通路**
（M1–M3：镜头 + 移动 + 目标 + 施法打断，只用战士和法师两个职业），
让核心手感尽早可以被人眼验证；确认手感成立后，再横向铺开职业、模式和装备系统。

理由：设计文档 1.1 明确核心支柱是「完整反制链」。这条链一旦手感不对，
后面 8 职业 × 10 技能的工作量全部要返工。先验证最贵的假设。

```
M0 文档与骨架
      │
M1 3D + 镜头 + 移动物理  ──┐
      │                   ├─ 到这里可以「跑起来看」，是第一个可演示节点
M2 目标 + 施法 + 打断    ──┘
      │
M3 六类瞄准 + 距离/视线/形状判定
      │
      ├──────────────┬──────────────┐
M4 八职业完整技能   M5 竞技场模式    M8 表现层与可读性
      │              │              │
      │         M6 临时武装系统      │
      │              │              │
      └──────► M7 夺旗战场 ◄─────────┘
                     │
              M9 统计/观战/重连/可访问性/许可
```

## M1 — 3D 场景、自由镜头与移动物理

**目标**：一个角色能在有墙有柱有台阶的场景里跑起来，镜头手感对。

| 交付物 | 位置 |
|---|---|
| three.js 渲染循环、场景图、固定时间步 | `packages/client/src/render/` |
| 镜头控制器：连续缩放（第一人称↔最远第三人称）、左键环绕/右键联动、碰撞拉近、复位 | `packages/client/src/camera/` |
| 输入层：WASD/QE/Space、可重绑映射表 | `packages/client/src/input/` |
| 角色控制器：滑墙、跨越低障碍、坡度判定、跳跃动量 | `packages/shared/src/sim/movement.ts` |
| 测试地图（盒子几何，无外部素材） | `packages/shared/src/data/maps/testbed.ts` |

**验收用例**（对应规格书 19.2）
`#1` 连续缩放 · `#2` 左键环绕不改朝向、右键联动 · `#3` 镜头不穿墙、靠墙拉近平滑恢复
`#44` 沿墙滑动/跨越低障碍/上下楼梯/不能斜向爬陡坡 · `#45` 跳跃保留水平动量、有限空中修正、不增速不瞬反
`#47` 动作状态不因单帧抖动反复切换

**关键陷阱**
- 镜头手动拖动期间必须停止自动跟随（4.3），否则会和玩家输入抢镜头产生摆动
- 第一人称只改变观察方式，**不改变**瞄准、射程、命中体积或攻击优势（4.1）
- 最远距离仍围绕角色，不能变成垂直俯视；角色高度约占画面 4%–8%（4.1）

|---|---|

| 四种动作类型：瞬发/读条/引导/瞄准射击 | 同上 |
| 打断结算：学派锁定、物理射击不锁学派、打断落空仍进 CD | `packages/shared/src/sim/interrupt.ts` |
| 假读条：主动取消不消耗资源与冷却 | 同上 |
| 施法条 HUD（技能名、学派、剩余时间、可否打断的盾牌标记） | `packages/client/src/hud/CastBar.ts` |

**验收用例**
`#4` 五种选目标方式 · `#6` 硬目标超距/被遮挡仍保留但显示不可用原因
`#13` 四类动作不同中断规则 · `#14` 普通伤害默认不取消也不延长施法
`#15` 专用打断停止可打断法术并锁学派 · `#16` 打断物理射击准备不产生学派锁定
`#17` 沉默不阻止物理射击、缴械不阻止纯魔法 · `#18` 假读条不消耗资源与冷却
`#19` 开始和完成时都检查目标/距离/视线/朝向 · `#20` 失败不产生重复伤害/扣资源/冷却异常

**关键陷阱**
- 「已经经过的公共冷却不返还」（7.4 第 6 条）—— 取消读条只退技能冷却和资源，不退 GCD
- 打断未命中、目标未在施法、技能不可打断时，**打断技能仍进入冷却**（7.2）
- 专用打断不触发 GCD（7.2），必须能在进攻技能之间穿插

## M3 — 六类瞄准、距离基准、视线与范围形状

**目标**：「所见即所中」。客户端画的指示器和服务器判定必须是同一份几何代码。

| 交付物 | 位置 |
|---|---|
| 六类瞄准的输入流程（直接/地面/直线/锥形/自身中心/碰撞投射物） | `packages/client/src/targeting/` |
| 地面指示器：真实外边界、中心点、最大距离、被墙阻挡、超出地图；非法位置不可确认 | `packages/client/src/targeting/GroundIndicator.ts` |
| 六种范围形状判定（单体/圆/锥/直线/环/链） | `packages/shared/src/math/geometry.ts`（M0 已完成） |
| 锁定投射物 vs 碰撞投射物两套结算 | `packages/shared/src/sim/projectile.ts` |
| 视线：胸口到胸口、低矮物体不挡 | `geometry.ts` 的 `hasLineOfSight` |

**验收用例**
`#7` 六类瞄准可区分 · `#8` 非法地面位置不能确认、边界与判定一致
`#9` 五档距离基准统一 · `#10` 模型大小/帽子/武器不改变碰撞体
`#11` 墙柱门挡视线、低矮物不误判 · `#12` 锁定与碰撞投射物命中规则不同

**关键陷阱**
- 非法位置提示**不能只靠红绿颜色**（5.5），必须配合降低亮度/叉号/虚线边界（可访问性 17.2）
- 环形技能必须**同时**显示内圈和外圈（14.3）
- 镜头拉远不增加技能距离，第一人称不提高命中精度（6.2）

## 跨里程碑的持续要求

这些不属于某一个里程碑，而是**每次提交都要满足**：

1. **一切数值来自 `docs/00-design-spec.md`**。改数值先改文档，再改代码，并在 PR 描述里引用章节号。
2. **客户端预览与服务器判定共用同一份几何代码**（`packages/shared/src/math/geometry.ts`）。
   任何在客户端单独实现的命中判定都是 bug。
3. **权威在服务器**。客户端只做预测和表现，不决定伤害、命中、拾取归属。
4. **每完成一个里程碑，更新三处**：`docs/PROGRESS.md`、`docs/10-acceptance-tracking.md`、本文件（如计划有调整）。
5. **不能用伪代码或占位图冒充完成**（附录A#7）。未做完就在 PROGRESS 里写「未完成」，不要写「已完成（待完善）」。
