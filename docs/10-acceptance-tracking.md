### 1. 抗法型护甲的「魔法控制承受降低」只实现了一半 —— ✅ **M11 已解决**

| 项 | 内容 |
|---|---|
| **偏差** | ~~10.8 抗法型护甲的优势写作「法术伤害与**魔法控制**承受降低」，当前只实现了法术伤害那一半~~ |
| **涉及条款** | 10.8 / 17.1 |
| **原因（历史）** | schema 只有全局的 `ccDurationTaken`，写成全局 0.8 会顺带削减物理控制 —— 那是抗控型护甲的身份，两件护甲会互相踩线。**宁可少表达一半优势，也不要表达错** |
| **解决** | M11 给 `AuraModifiers` 加了 `ccDurationTakenBySchool`，`applyControl()` 从 `ctx.skillId` 反查 `SkillDef.school`，抗法护甲已接上，advantage 文案改回「法术伤害与魔法控制时长降低」。★ 测试的重点是**物理学派必须是 undefined** —— 那才是它与抗控型的分界线 |

### 2. 16.2「增益期间击杀」恒为 0 —— ✅ **M16 已解决**

| 项 | 内容 |
|---|---|
| **偏差** | ~~`ArenaStats.killsDuringBuff` 目前恒为 0~~ |
| **涉及条款** | 16.2 |
| **原因** | 消耗品能被拾取（`DropKind` 含 `'consumable'`），但 sim 里没有任何地方**使用**它们产生增益 —— 所以「增益期间」这个状态从不存在。★ 按附录A#7，如实记为缺口，而不是用一个恒为 0 的字段冒充完成 |
| **是否修正** | 计划修正。`recordItemBuff()` 已留好唯一入口，消耗品接上使用路径后这一项自然有值 |
| **⚠️ M11 核查更正（历史）** | 缺口比原记载更大：`data/schema.ts` 里**根本没有 `ConsumableDef`**（没有名字、效果表、持续时间、冷却），也**从没有代码创建过 `kind:'consumable'` 的掉落物**，`Loadout.consumables` 至今只被赋值过 `[]`。所以修正它的工作量是「新增数据类型 + 注册表 + 拾取 + 使用 + 统计接线」，不是补一个函数 |
| **解决（分两轮）** | · **M11-6** 补齐了 sim 侧：`ConsumableDef` + `data/consumables.ts` 注册表 + `takeConsumable()` + `tickWorld` 的结算步 + `recordItemBuff()` 接线 + 军械箱会刷消耗品掉落。<br>· **M16** 补齐了**可达性** —— 这才是它真正卡住的地方：在此之前服务器从不调用 `setupArmories()`／`spawnDropsFromRoster()`（场上一件掉落都没有）、快照不带 `drops`（客户端看不见）、客户端从不发 `InteractStart`／`UseConsumable`（捡不了也用不了），而且房间默认经典竞技场（按 #28 本就不刷任何临时武装，连开关都没有）。四条断一条这项统计就仍然恒为 0。<br>★ 端到端断言：`verify:m16` #11（捡到）→ #11b（进道具栏）→ #13（用出来、光环生效） |
| **★ 教训** | 这一条在 M9 记为「没有使用路径」、M11 更正为「连数据类型都没有」、M11-6 补完 sim 后**文档没有再更新**，于是 docs/14 §16c 直到 M16 还写着「`ConsumableDef` 数据类型都不存在」。**把已完成的事记成未完成，和把未完成记成已完成一样有害** —— 它让下一个人重做一遍，或者以为还有很多工作而不敢动 |
