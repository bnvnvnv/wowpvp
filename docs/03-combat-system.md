# 战斗系统实现设计

> 覆盖规格书第 5–8 章：目标选择、攻击距离与命中、施法打断、通用战斗规则。
> 这是整个项目最容易做错的部分 —— 52 条验收标准里有 20 条集中在这里。

## 1. 目标系统（规格书 5.x）

### 1.1 五个目标槽位

| 槽位 | 生命周期 | 谁能覆盖它 |
|---|---|---|
| **硬目标** `hard` | 持续保留，直到玩家切换、目标离场或主动清除 | 点击、Tab、队伍框点击 |
| **焦点目标** `focus` | 独立保存，与硬目标互不影响 | 焦点快捷键（再次按下清除） |
| **鼠标指向** `mouseover` | 仅当前帧有效 | 鼠标悬停人物模型或队伍框 |
| **软提示** `soft` | 仅高亮，**不自动成为攻击目标** | 屏幕中心附近的候选 |
| **目标的目标** `targetOfTarget` | 派生，只读 | 由硬目标的当前目标推导 |

**易错点**：软提示目标绝不能被技能直接使用。它只负责高亮，玩家必须点击或 Tab 后才锁定（5.1）。

### 1.2 技能取目标的优先级

```
鼠标指向目标（若技能支持且鼠标正悬停在合法目标上）
  → 硬目标
  → 自我（仅当技能可对自己使用且按住自我施法键）
  → 失败：CastFailure.NoTarget
```

**攻击型直接目标技能在没有目标时不自动攻击随机敌人**（5.6），只提示「需要目标」。
「无目标时选择最近正面敌人」的辅助选项**默认关闭**，标准竞技规则下不可开启。

### 1.3 Tab 循环（5.3）

候选集过滤，按顺序：

1. 距离 ≤ 45 米（`RANGE.MAX_SELECT`）
2. 位于**当前镜头**前方 140°（`TARGETING.TAB_FRONT_ARC_DEG`）内 —— 完全在身后的不进首轮列表
3. 敌对、存活、可被选中
4. **排除未被发现的潜行目标**（见 §1.4）
5. 宠物与召唤物默认排除，玩家可在设置中加入

排序优先级（依次比较）：

```
① 接近屏幕中心   ② 距离更近   ③ 当前可见   ④ 正在施法   ⑤ 敌方旗手
```

被完整墙体遮挡的目标**可以保持已选中状态**，但不优先进入新的 Tab 候选（5.3）。
即：遮挡影响「进候选」，不影响「保持选中」。

### 1.4 潜行的安全边界（验收 #5）

> 潜行且未被发现的目标不能被点击、Tab、姓名板或小地图选中。

**这条必须在服务器实现，不能只在客户端隐藏。**
未被发现的潜行目标**根本不出现在发给该客户端的快照里**（见 [08-network-protocol.md](08-network-protocol.md) 视野裁剪）。
如果只做客户端过滤，改一行前端代码就能作弊。

发现条件：3 米内可能被发现、照明弹区域内被揭露、旗手不能潜行、持旗时禁止进入潜行。

## 2. 距离、视线与朝向（规格书 6.x）

### 2.1 三种距离算法

| 场景 | 算法 | 实现 |
|---|---|---|
| 近战（≤ 4 米） | **碰撞体边缘之间**的水平距离 | `geometry.edgeDistance` |
| 远程（> 4 米） | 施法者胸口 → 目标胸口，再扣掉目标碰撞体半径 | `geometry.rangedDistance` |
| 选中距离 | 中心点直线距离 | `vec3.distance` |

近战额外检查高度差 ≤ `GEOMETRY.VERTICAL_TOLERANCE`（2.5 米），
避免站在小台阶上互相打不到 —— 但也不允许隔着两层楼互砍。

> **验收 #10**：角色视觉大小、帽子和武器不会改变战斗碰撞体与被选中难度。
> 实现方式：`GEOMETRY.HITBOX_RADIUS` / `HITBOX_HEIGHT` 是全局常量，
> 所有人形职业共用，模型缩放只影响渲染，不传入任何判定函数。

### 2.2 视线（6.4）

胸口到胸口的线段，与所有 `blocksSight !== false` 的 AABB 求交。

低矮栏杆、只遮挡脚部的物体在地图数据里标 `blocksSight: false`，
这样它们挡移动但不挡视线，满足「不应频繁造成无视线」（6.4）。

地面技能落点的合法性用同一套逻辑：施法者胸口 → 落点上方 0.5 米（`isGroundPositionLegal`）。

### 2.3 朝向（6.5）

```ts
isFacing(actorPos, actorYaw, targetPos, 180)   // 正面 180°
isBehind(attackerPos, targetPos, targetYaw, 120) // 背刺 120°
```

> **只旋转镜头不会改变角色朝向，因此不能通过看向目标绕过朝向限制。**（6.5）

实现约束：`isFacing` 的第二个参数**必须**是角色 yaw，不能是镜头 yaw。
客户端左键环绕（4.2）只改镜头 yaw，右键拖动才同时改角色 yaw。
把这两个值分开存储，命名为 `character.yaw` 和 `camera.yaw`，避免混用。

### 2.4 六种范围形状（6.3）

| 形状 | 参数 | 判定函数 | 表现要求 |
|---|---|---|---|
| 单体 | — | 目标合法性检查 | — |
| 圆形 | 中心 + 半径 | `hitCircle` | 边界全程可见 |
| 锥形 | 角度 + 距离 | `hitCone` | 显示角度和距离，背后目标不受影响 |
| 直线 | 长度 + 宽度 | `hitLine` | — |
| 环形 | 内半径 + 外半径 | `hitRing` | **必须同时显示内外边界** |
| 链式 | 首目标 + 跳转距离 + 最大目标数 | `nextChainTarget` | — |

锥形判定做了碰撞体切线补偿（`asin(r/d)`），避免贴脸大目标因中心点差半度而漏判。

### 2.5 两类投射物（6.6 / 验收 #12）

| | 锁定投射物 | 碰撞投射物 |
|---|---|---|
| 命中确认 | **释放瞬间**确认命中资格 | 沿真实方向飞行并碰撞 |
| 目标移动 | 不会自然落空 | 可以躲避 |
| 墙体 | 不受影响（已确认） | 被阻挡 |
| 仍可反制 | 免疫、吸收、反射 | 免疫、吸收、反射、走位、墙体 |
| 例子 | 火球、审判、风暴之锤、普通箭矢 | 穿透箭、直线魔法弹 |
| 数据表达 | `Targeting.Direct` + 客户端飞行表现 | `EffectDef { kind: 'spawnProjectile' }` |

**第三类：延迟落点**（陨石、箭雨）。目标地面区域在延迟后结算，
落点边界和倒计时**全程可见**（14.3）—— 这是它的唯一反制方式，绝不能隐藏。

## 3. 施法与打断（规格书 7.x）—— 核心

### 3.1 四种动作类型的中断矩阵（验收 #13）

| | 瞬发 | 读条 | 引导 | 瞄准射击 | 普通自动攻击 |
|---|---|---|---|---|---|
| 有施法条 | ✗ | ✓ | ✓ | ✓（物理准备条，独立颜色） | ✗ |
| 专用打断 | ✗ | ✓ | ✓ 终止剩余 | ✓ 仅取消本次 | **✗** |
| 沉默 | 魔法则禁用 | ✓ | ✓ | **✗** | ✗ |
| 缴械 | 武器技能则禁用 | ✗ | ✗ | ✓ | ✓ 阻止下一发 |
| 硬控制 | 同时到达可阻止 | ✓ | ✓ | ✓ | ✓ 阻止下一发 |
| 主动移动 | ✗ | 仅「原地施放」 | 由技能标记决定 | ✓ | ✗ |
| 强制位移 | ✗ | ✓ | ✓ | ✓ | — |
| **普通伤害** | ✗ | **✗** | **✗** | **✗** | ✗ |
| 产生学派锁定 | — | 魔法→是 | 魔法→是 | **否** | — |

> **验收 #14：普通伤害默认不会取消或延长施法。**
> 只有技能明确带「打断」或控制效果时才中止。这是与很多游戏不同的地方，很容易实现错。

> **验收 #16/#17**：打断物理射击准备**不产生**魔法学派锁定；
> 沉默**不能**阻止物理射击，缴械**不能**阻止纯魔法施法。

### 3.2 施法生命周期状态机（7.4）

```
        按下技能
           │  ① 检查：目标类型 / 资源 / 沉默或缴械 / 技能冷却 / GCD
           ▼
     ┌──────────┐   ② 显示施法条或射击准备条，启动 GCD
     │ Starting │
     └────┬─────┘
          ▼
     ┌──────────┐   ③ 每 tick 检查：移动 / 控制 / 强制位移 / 打断
     │ Casting  │─────────┐
     └────┬─────┘         │ 被中断
          │ 时间到         ▼
          │          ┌────────────┐
          │          │ Interrupted│  不产生效果
          │          └────────────┘  资源与技能冷却不消耗
          ▼                          已经过的 GCD 不返还 ★
   ④ 完成瞬间再次检查
     目标存活 / 距离 / 视线 / 朝向 / 地面落点合法
          │
     ┌────┴────┐
     ▼         ▼
 ┌────────┐ ┌────────┐
 │Success │ │ Failed │
 └────────┘ └────────┘
  ⑤ 消耗资源  ⑥ 不产生效果
     进冷却      不消耗资源与冷却
     结算效果
```

**★ 第 6 条最容易漏**：「失败或主动取消不消耗资源与技能冷却，但**已经经过的公共冷却不返还**」（7.4）。
这是假读条博弈的成本，不能退。

**第 ① 步和第 ④ 步必须调用同一个 `validate()` 函数**（验收 #19），
差异只在于第 ④ 步额外检查「目标是否仍然存活」。

### 3.3 专用打断（7.2）

```
命中正在进行的读条 / 引导 / 瞄准射击
  ├─ 被打断的是魔法 → 立即停止 + 同学派锁定 3 秒（法师反制 4 秒）
  └─ 被打断的是物理射击准备 → 只取消本次射击，无学派锁定

未命中 / 目标未在施法 / 技能标记为不可打断
  └─ 无事发生，但打断技能**仍然进入冷却** ★
```

**专用打断不触发公共冷却**（`triggersGcd: false`），便于在进攻技能之间穿插。

八个职业各自的专用打断（验收 #21，测试会断言这条）：

| 职业 | 打断技能 | 距离 | 冷却 | 学派锁定 |
|---|---|---|---|---|
| 战士 | 拳击 | 3 米 | 15 秒 | 3 秒 |
| 圣骑士 | 责难 | 3 米 | 15 秒 | 3 秒 |
| 死亡骑士 | 心灵冰冻 | 15 米 | 15 秒 | 3 秒 |
| 盗贼 | 脚踢 | 3 米 | 15 秒 | 3 秒 |
| 猎人 | 反制射击 | 30 米 | 18 秒 | 3 秒 |
| 法师 | 法术反制 | 30 米 | 20 秒 | **4 秒** |
| 牧师 | 沉默 | 30 米 | 30 秒 | —（等价沉默 3 秒） |
| 德鲁伊 | 迎头痛击 | 13 米 | 15 秒 | 3 秒 |

### 3.4 假读条博弈（7.5 / 验收 #18）

玩家可通过移动、Esc 或再次按下技能主动取消读条。取消**不造成额外惩罚**。

对应的信息要求：敌方施法条**必须**显示技能名称、学派、剩余时间和是否可打断。
不可打断技能用明显的**盾牌标记**，避免玩家浪费打断后误以为系统失效（7.5）。

## 4. 通用战斗规则（规格书 8.x）

### 4.1 控制递减（8.2）

```ts
DR_WINDOW_SECONDS = 15
DR_LADDER = {
  stun:         [1, 0.5, 0.25, 0],   // 昏迷
  incapacitate: [1, 0.5, 0.25, 0],   // 恐惧 / 迷惑 / 变形
  root:         [1, 0.5, 0.25, 0],   // 定身（与普通减速分开！）
  silence:      [1, 0.5, 0],         // 只有三段
  knockback:    [1, 0.5, 0.25, 0],   // 击退 / 拉拽
}
```

每个实体对每个 `DrCategory` 维护 `{ count, expiresAt }`。
施加控制时：`实际持续时间 = 基础时间 × DR_LADDER[category][count]`，
系数为 0 表示免疫；随后 `count++`，`expiresAt = now + 15`。

**定身与普通减速是两条独立的链**，减速不参与递减。

### 4.2 通用解控「战斗意志」（8.3）

- 90 秒冷却，全职业共有
- 解除：昏迷、恐惧、迷惑、变形、定身
- **不能**解除：持续伤害、普通减速、沉默、降低治疗、战斗抑制
- 默认**允许在昏迷中使用**，UI 必须明确显示当前是否可用

数据层用 `AuraDef.clearableByTrinket` 标记。默认 `false` —— 只有明确标 `true` 的才被清除，
这样新增光环时不会因为忘记标注而意外可解。

### 4.3 效果叠加规则（8.4 / 17.1 / 验收 #23）

> 同类团队减伤、加速和治疗增益不能无限叠加；同类型效果取较强者或按衰减规则叠加。

`sim/modifiers.ts` 按 `AuraModifiers` 的每个字段分组聚合：

| 字段类别 | 聚合方式 |
|---|---|
| 减速（`moveSpeed < 1`） | **取最强的一个**，不叠乘 |
| 加速（`moveSpeed > 1`） | 取最强的一个 |
| 团队减伤（`damageTaken`） | 取最强的一个 |
| 个人减伤 vs 团队减伤 | 分组后组间相乘 |
| 受到治疗降低（`healingTaken`） | 取最强的一个 |
| 伤害提高（`damageDealt`） | 相乘（爆发窗口是设计意图） |

> **17.1**：所有玩家使用相同目标规则、范围、碰撞体和镜头限制。
> 同类控制、团队减伤、加速和治疗增益不能通过多职业重复无限叠加。

### 4.3b 暴击（⚠️ 规格书没有这条机制 —— docs/10 已知偏差 #7）

全职业**基础** 10% 几率、1.5 倍伤害/治疗（`CRIT`，constants/combat.ts）。
打击感改造引入的**玩法新增**；周期跳不暴击、倍率 1.5 不取 2.0 两条自我约束不变。

**P7 修正轴**（2026-08-06，用户点名「没有暴击体系」）：`AuraModifiers` 新增
- `critChance`（**加算**，与闪避/招架同约定）：实际几率 =
  clamp(10% + Σ修正, 0, **上限 50%**)。上限的理由：暴击的全部价值在不确定，
  叠到必暴它就退化成乘算增伤。
- `critDamage`（**乘算**，与 damageDealt 同约定）：实际倍率 = 1.5 × Π修正。

首批数据源（全部占位值，横向取舍框架内）：盗贼双匕首 +10% 几率、
战士双手巨剑 倍率×1.15、猎人长弓 倍率×1.2、进攻型护甲 +5% 几率、
圣骑义愤 10 秒 +15% 几率（第一个「爆发窗口」）。默认护甲仍是零修正基线。

一次伤害的完整结算顺序（`effects/combat.ts dealDamage`）：

```
免疫 → 规避(闪避/招架/格挡) → ★暴击 → 输出/承伤修正 → 背刺 → 取整
     → 护甲反推 → 吸收 → 扣血 → overkill/死亡
```

掷骰位置的三条理由：
- 在规避**之后** —— 被闪掉的一发**不消耗**攻击者的随机数。
  否则「对面开没开圣盾术」会改变后续全部暴击序列，回放不可复现
- 在吸收**之前** —— 护盾按暴击后的量消耗，「暴击被小盾吃满」也读得出暴击
- 在取整**之前** —— 先乘后取整，避免二次舍入

随机流纪律：**暴击掷攻击者的流，规避掷被攻击者的流**（`nextRandom` 按实体
分流的意义所在）—— 两边新增判定互不扰动。不暴击的路径：DoT/HoT/地面 tick
（`EffectContext.periodic`，由 tick.ts 标记）、8.5 压迫伤害（赛制机制不是攻击）。

### 4.4 竞技场战斗抑制（8.5）

```
时间 →  0        60s(2v2)   90s      120s     150s     180s
抑制    0%  ──────► 10% ────► 15% ────► 20% ────► 25% ────► …
                    每 30 秒 +5%，作用于所有治疗与吸收
```

抑制**只影响治疗和吸收**，不影响伤害。上限 `DAMPENING.MAX = 90%`，
避免出现治疗完全归零导致的除零与 UI 异常。

常规时间结束后进入**决胜阶段**：
所有玩家大致位置可见 → 潜行受限 → 抑制加速 → 逐步加入**不可完全免疫**的竞技场压迫伤害。

「不可完全免疫」意味着这个伤害必须绕过 `immuneAll` 标志，
在 `effects/damage.ts` 里做显式豁免，否则圣盾术／寒冰屏障能无限拖延（验收 #27）。

## 5. 实现顺序建议

按这个顺序做，每步都能独立验证：

1. `geometry.ts` 的判定函数 + 单元测试（**已完成于 M0**）
2. `targeting.ts`：五个槽位 + Tab 循环 → 测试：潜行不进候选、身后不进首轮
3. `casting.ts`：状态机骨架，只支持瞬发和读条 → 测试：开始/完成两次校验
4. `interrupt.ts`：专用打断 + 学派锁定 → 测试：物理射击不锁学派、打断落空仍进 CD
5. `aura.ts` + `dr.ts`：光环与递减 → 测试：四次昏迷后免疫、沉默三段
6. `effects/`：逐个 kind 注册处理器
7. `modifiers.ts`：聚合规则 → 测试：两个减速不叠乘
8. `dampening.ts`：抑制曲线

每一步的测试文件与实现同目录，命名 `<模块>.test.ts`。
