# 素材许可清单

> 规格书 18.2 与附录A#6：**素材必须先完成许可清单；未明确授权的图标、模型、音效和字体不得进入正式包。**
> 验收 #51：外部素材均有许可记录，不包含禁止再分发的项目专属资产。
>
> **顺序不能反：先登记，后使用。** 未登记的文件不允许出现在 `assets/` 里。

## 0. 当前项目定位：**个人用途**，但仓库是公开的

本项目目前是**个人开发用途**，不发布、不商用。所以「个人使用允许」的素材是可以下载使用的。

★★ **但有一条界线不能跟着放松：**

> **「个人使用」许可你下载、本地运行、截图；它不许可你把文件提交到公开仓库。**
>
> 本仓库有公开远端（`github.com/bnvnvnv/wowpvp`），
> **`git push` 就是再分发** —— 那是与「使用」不同的一项权利。
> 「仅限个人使用」的素材一旦提交，就已经违反了它的许可，而且 git 历史很难彻底清除。

所以本文件把素材分成**三档**，而不是一档「能用/不能用」。
每一档解锁的权利不同，登记表里也要记清每个文件属于哪一档：

| 档位 | 解锁什么 | 判据 | 文件放哪 |
|---|---|---|---|
| **T1 个人开发期可用** | 下载到本地、跑起来、截图 | 许可允许个人/非商业使用 | `assets/local/`，**已 gitignore** |
| **T2 可入库** | 可以 `git commit` 并推到公开仓库 | 许可**明确允许再分发** | `assets/`，入库 |
| **T3 可商用发布** | 可以进正式发布包 | T2 + **非 NC** + 署名义务已履行 | `assets/`，入库 |

★ 三档是**递进**的：T3 ⊂ T2 ⊂ T1。
一个素材可以是 T1 但不是 T2（例如 Mixamo 的 FBX、DaFont 的多数字体），
也可以是 T2 但不是 T3（例如 CC-BY-**NC** 的音效）。

★★ **这个分档的意义在于：它让「悄悄升级」变得不可能。**
如果只有一档「能用」，那么某个「仅个人使用」的素材会在某次 `git add .` 里
静默进入仓库，也会在将来某次发布里静默进入发布包 —— 而两次都不会有任何东西报错。
分档之后，升级必须显式改登记表里的档位字段，那是一次显眼的改动。

## 1. 核心原则

| 原则 | 说明 |
|---|---|
| **代码与素材许可分开管理** | 本仓库代码是 MIT，但**这不覆盖任何媒体资产**。参考项目是 MIT 不等于它引用的所有模型/图标都能自由使用（18.1） |
| **逐项登记** | 每个模型、动画、图标、音效、字体都要单独一行：名称、作者、来源、许可证、署名要求、商业使用、修改、再分发 |
| **授权不清晰 = 不能用** | 「看起来像免费的」「网上到处都有」不构成授权（18.2） |
| **不碰暴雪资产** | 不使用暴雪的角色模型、纹理、技能图标、地图文件、Logo、音频，不直接复刻场景布局（18.3） |

## 2. 按三档分类

### T3 可商用发布（最宽的权利，最严的判据）

- **CC0 / 公有领域**：[Kenney](https://kenney.nl)、[Quaternius](https://quaternius.com)、
  KayKit 中**明确标记为 CC0** 的部分
- **OFL / Apache-2.0 字体**：[Google Fonts](https://fonts.google.com)
- 明确允许商业使用与再分发的 **CC-BY**（**必须按要求署名**，
  署名文本写进本文件和游戏内致谢页）
- 自制原创素材

### T2 可入库但不可商用

- **CC-BY-NC** / **CC-BY-NC-SA**：允许再分发，但禁止商业使用。
  ★ 个人项目可以用、可以入库，但**发布前必须清空**，否则 #51 的审计会挂。
  登记表里的「商用」列必须写 `否`。
- **CC-BY-SA / GPL 素材**：允许再分发，但**有传染性** ——
  ★ 本仓库代码是 MIT，混入 GPL 素材可能要求整体以 GPL 分发。
  用之前必须确认该许可的传染范围只覆盖素材本身，不波及代码。

### T1 仅个人开发期可用 —— **不得入库**

以下这些**可以下载到 `assets/local/`（已 gitignore）本地用**，但一个文件都不能提交：

- **Mixamo**（Adobe）：许可允许在作品中使用，但**不允许再分发原始 FBX**
- **DaFont** 上标注「free for personal use」的字体
- **Itch.io / Sketchfab / Free3D** 上标注「personal use only」的素材
- 任何找不到明确再分发许可、但明确允许个人使用的素材

★ 用它们做出的**截图和视频**可以入库（那是作品，不是素材文件），
  但要在登记表里记明来源，将来替换素材时才知道哪些画面需要重拍。

### ❌ 任何档位都不可用

- 暴雪的一切资产：角色模型、纹理、技能图标、地图文件、Logo、音频、UI 素材（18.3）
- CraftPix 技能图标（18.2 明确点名）
- 参考项目 [world-of-claudecraft](https://github.com/levy-street/world-of-claudecraft) 的
  **定制武器、商店图、成就图标、品牌标识**，以及任何标记为「需要许可」的素材（18.2）
- **TurboSquid Free**：标准许可**禁止再分发**，且不豁免个人项目 ——
  连 T1 都不给，因为它的条款限制的是「使用」本身的分发形态
- **BBC Sound Effects**：许可限定**个人/教育**用途且禁止再分发。
  ★ 严格说属于 T1，但它的条款对「作品中使用」也有限制，
  为省事直接排除 —— Freesound 上的 CC0 音效能覆盖同样的需求
- 任何**未登记或授权不清晰**的素材（「网上到处都有」不构成授权，18.2）

### ⚠️ 关于参考项目

规格书 18.1 说得很清楚：

> 该仓库可以作为**人物、动作、移动手感、镜头碰撞和技能特效组织方式**的参考，
> 但**不能把所有媒体资源都视为 MIT 可自由使用**。

即：可以参考它**怎么做**，不能直接拿它的**素材文件**。
参考其骨骼命名约定、武器挂点结构、动画状态切换方式是允许的；
复制它的模型文件、贴图、图标不是。

## 3. 原创边界（18.3）

正式发布必须使用**原创**的：

- 游戏名称、阵营名称
- 职业包装（可以叫「战士」这类通用词，但职业标志、外观、口号必须原创）
- 技能名称（当前代码里用的是规格书给的中文名，**发布前需要一轮改名评估**）
- 地图、美术、音效、UI

可以参考的是：职业分工、目标制战斗、控制/打断/驱散博弈、自由镜头体验 —— 这些是**玩法机制**，不受版权保护。

> 📌 **待办**：当前代码中的技能名（冲锋、致死打击、圣光术…）直接来自规格书，
> 与《魔兽世界》技能名高度重合。发布前必须做一轮重命名。
> 由于技能名只在 `SkillDef.name` 一个字段里，改名成本很低 —— 但**不要拖到最后**。
> 已登记在 [10-acceptance-tracking.md](10-acceptance-tracking.md) 的待确认问题里。

## 5. 当前素材状态

**本仓库到 M8 为止仍不包含任何外部媒体资产。**

M0–M8 的所有可视内容都用 three.js 的程序化几何体（盒子、胶囊、圆柱、圆环、
八面体）与纯色材质构建，不依赖任何外部文件。这是有意为之：

1. 在核心手感验证完成前引入美术资产是浪费
2. 程序化几何体让「统一战斗碰撞体」（13.2 / 验收 #10）天然成立 —— 没有模型胖瘦差异
3. 避免在早期就背上许可包袱

### ★ M8 的决定：表现层继续保持全程序化

M0 时本节写的是「引入外部素材的时机：M8（表现层）」。M8 开工时重新评估，
**决定继续不引入**，理由是三条规格书要求恰好都更容易用程序化几何满足：

| 要求 | 程序化的好处 |
|---|---|
| 14.4 低画质不能隐藏关键信息（验收 #48）| 纯色 + 几何体在最低画质下退化可控；贴图与粒子在低画质下往往整体关闭，容易连关键信息一起关掉 |
| 17.2 不能只靠颜色区分（可访问性）| 每种状态用**形状 + 挂点 + 运动**三通道区分，几何体天然支持；换成图标贴图就退回「一张图不同颜色」 |
| 附录A#5 素材必须先完成许可清单 | 没有素材 = 没有清单要填，也没有许可风险 |

代价要说清楚：**画面会明显朴素**，没有贴图、法线、粒子纹理和骨骼动画。
这是一次**推迟**而不是取消 —— 引入美术的正确时机是玩法与可读性验收全部通过之后，
那时才知道每个特效真正需要什么。

**引入外部素材的时机**：M12（见 [13-roadmap-post-m9.md](13-roadmap-post-m9.md)），
或任何时候只要先走完 §6 的流程。
**流程不能跳**：先填 §4 登记表 → 再下载文件（附录A#5）。

### ★ M12 的定位：个人用途，可以放宽「用什么」，不能放宽「提交什么」

M9 完成后项目定位明确为**个人开发用途**（§0），所以 T1 档的素材
（Mixamo 动画、DaFont 字体、Sketchfab 上「personal use」的模型）
**可以下载到 `assets/local/` 使用** —— 这比 M8 时的判断放宽了。

但 §0 那条界线不放宽：**它们一个文件都不能入库。**
仓库有公开远端，`git push` 就是再分发。

## 6. 素材引入流程

```
1. 找到候选素材
2. 确认许可证 —— 找到明确的 LICENSE 文件或授权页面，截图/存档留证
3. ★ 判档位（§0 的三档）：它允许再分发吗？允许商用吗？
4. 在本文件第 4 节登记表加一行，**含档位列**
5. 若是 CC-BY 等需署名的许可证：
   同时把署名文本加入 assets/ATTRIBUTION.md 和游戏内致谢页
6. 按档位放文件：
     T1 → assets/local/   （已 gitignore，**不要 git add**）
     T2 / T3 → assets/    （入库）
7. 提交时在 commit message 里写明素材来源、许可证与档位
```

**任何跳过第 2、3、4 步的提交都应当被拒绝。**

★ 第 6 步是最容易出事的一步，因为 `git add .` 会顺手把一切都加进去。
所以 `assets/local/` 已经写进 `.gitignore` —— **靠工具挡，不靠记性**。

## 7. 发布前审计清单与**外部素材清单**

### 7.1 M9 结论：零外部素材

**验收 #51 要求「外部素材均有许可记录」。M9 完成时的事实是：**

> **本仓库不包含任何外部素材，因此外部素材清单为空。**
> **目前没有任何外部素材** —— 这条验收天然满足，而不是「填好了表」。

机器可核对的判据（`pnpm verify:m9` 的 #51 会检查，`ls` 可复核）：

| 判据 | 状态 |
|---|---|
| 仓库内不存在 `assets/` 目录 | ✅ |
| 不存在任何 `.png` / `.jpg` / `.gltf` / `.glb` / `.fbx` / `.wav` / `.mp3` / `.ogg` / `.ttf` / `.woff*` 文件（`scripts/_verify-*.png` 是验收脚本生成的截图产物，不是素材，且不入库）| ✅ |
| `package.json` 依赖里没有任何素材包 | ✅ |
| 全部可视内容由 three.js 程序化几何体 + 纯色材质构成 | ✅ 见 §5 |

**这条验收的「重启条件」**：一旦引入第一个**入库**（T2/T3）文件，本节的结论立即失效，
必须先走完 §6 流程并把该文件登记进 §4 的表格。**流程不能跳**（附录A#5：
素材必须先完成许可清单再下载）。

★ 注意：往 `assets/local/` 放 T1 素材**不会**让 #51 失效 ——
#51 的原文是「**外部素材**均有许可记录」，而 T1 素材同样要登记进 §4 的表。
真正会让它失效的是「有文件但没登记」，与在哪个目录无关。

### 7.2 引入素材后才需要的清单

以下清单在 §7.1 的结论失效之后才有内容可填：

- [ ] `assets/` **与 `assets/local/`** 下每一个文件都能在第 4 节登记表里找到对应行
- [ ] ★ 登记表里没有任何 `T1` 行的路径落在 `assets/local/` 之外（否则它已被再分发）
- [ ] ★ 发布包里**不含** `T1` 与 `T2` 素材 —— 只有 `T3` 能进正式发布
- [ ] 登记表里每一行的来源 URL 仍然有效，许可证未变更
- [ ] 所有需署名的素材已在 `assets/ATTRIBUTION.md` 和游戏内致谢页署名
- [ ] 没有任何 NC（非商业）限定素材
- [ ] 没有暴雪资产，没有参考项目的定制资产
- [ ] 技能名、地图名、职业标志已完成原创化改写（见 §3）
- [ ] 字体许可证单独确认（字体常有独立于图像素材的分发限制）
- [ ] 音效与音乐许可证单独确认
