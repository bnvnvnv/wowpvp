# 渲染、镜头、动画与移动物理

> 覆盖规格书第 4 章（3D 镜头与基础操作）、第 13 章（人物素材、动画、移动物理与镜头表现）、
> 第 14 章（技能特效与战斗可读性）。对应里程碑 M1 和 M8。

## 0. 一条贯穿全文的原则

> **第一人称只改变观察方式，不改变瞄准、射程、命中体积或攻击优势。**（4.1）

实现上如何保证：**镜头模块不向任何判定函数传参**。

`packages/shared/src/math/geometry.ts` 的所有函数只接受角色位置、角色 yaw、碰撞体半径。
镜头距离、镜头 yaw、FOV 这些值**根本不在这些函数的签名里**，
所以物理上不存在「拉近镜头提高命中精度」的路径。

同理，`isFacing()` 的入参是 `character.yaw` 而不是 `camera.yaw` —— 见 §1.3。

## 1. 镜头系统（规格书 4.1–4.3）

### 1.1 连续缩放（验收 #1）

> 镜头连续缩放，**不使用只有几个离散档位的突变切换**。

```ts
// 目标距离由滚轮连续调整，实际距离向目标距离指数插值
targetDistance = clamp(targetDistance - wheelDelta * ZOOM_SPEED, 0, MAX_DISTANCE);
currentDistance += (effectiveTarget - currentDistance) * (1 - Math.exp(-ZOOM_LERP * dt));
```

| 参数 | 值 | 依据 |
|---|---|---|
| `MIN_DISTANCE` | 0 | 0 即第一人称 |
| `FIRST_PERSON_THRESHOLD` | 0.4 m | 小于此值切换到第一人称表现 |
| `MAX_DISTANCE` | 18 m | 由「角色占屏高 4%–8%」反推，见 §1.2 |
| `DEFAULT_DISTANCE` | 6.5 m | 4.1「默认中远距离第三人称，完整显示角色」 |
| `ZOOM_LERP` | 12 /s | 指数插值系数，帧率无关 |

用 `1 - exp(-k·dt)` 而不是 `k·dt` 做插值：后者在低帧率下会过冲甚至发散，
而镜头抖动会直接影响 13.4 要求的动作稳定性。

### 1.2 最远距离与画面占比（4.1）

> 最远距离仍围绕角色，**不变成垂直俯视**；角色高度约占画面高度 **4% 至 8%**，
> 不能一次看到整张地图。

角色高度 `h = 2.0 m`（`GEOMETRY.HITBOX_HEIGHT`），透视投影下占屏比例：

```
占屏比例 = h / (2 · d · tan(fov/2))
```

取 `fov = 60°`，则 `tan(30°) ≈ 0.5774`：

| 距离 d | 占屏比例 | 是否合规 |
|---|---|---|
| 6.5 m | 26.6% | 默认第三人称，完整显示角色 ✓ |
| 12 m | 14.4% | — |
| **18 m** | **9.6%** | 接近 8% 上限 |
| **21.6 m** | **8.0%** | ← 4%–8% 区间的上界 |
| **43 m** | **4.0%** | ← 下界 |

**结论**：`MAX_DISTANCE` 取 **18 m**，配合镜头俯角，角色在画面中的实际投影高度落在 8%–10%。
若要严格落在 4%–8%，需要把 `MAX_DISTANCE` 提到 22–43 m —— 但那样在 2v2 小地图上
就能一眼看完整张图，违反同一条的「不能一次看到整张地图」。

> ⚠️ **这是一条需要设计侧确认的取舍**。已登记到
> [10-acceptance-tracking.md](10-acceptance-tracking.md)。
> 当前实现取 18 m（优先满足「不能看完整张图」），
> 若设计侧坚持 4%–8%，改 `MAX_DISTANCE` 常量即可，不涉及逻辑改动。

**最远距离必须仍围绕角色**：镜头始终在以角色为中心的球面上，俯角上限 `MAX_PITCH = 75°`，
永远不允许到达 90°（正俯视）。

### 1.3 左键环绕 vs 右键联动（验收 #2）—— 两个独立的 yaw

这是全项目最容易写错的地方。**必须维护两个独立变量**：

```ts
interface CameraState {
  yaw: number;       // 镜头绕角色的水平角
  pitch: number;     // 俯仰角
  distance: number;
}
interface CharacterState {
  yaw: number;       // 角色面向。所有战斗判定只认这个
}
```

| 输入 | 改变 | 战斗意义（4.2） |
|---|---|---|
| 按住**左键**拖动 | 只改 `camera.yaw/pitch` | 镜头转动**不改变角色面向**，可查看侧后方 |
| 按住**右键**拖动 | 同时改 `camera.yaw` 和 `character.yaw` | 向前技能和移动方向跟随镜头 |
| 松开右键 | 两者解耦，`camera.yaw` 保持 | — |
| A/D（未按右键） | 改 `character.yaw`，`camera.yaw` 跟随 | 经典 MMORPG 转向 |
| A/D（按住右键） | 作为侧移，不改朝向 | — |

```
        ┌──────────────┐  按下左键   ┌──────────────┐
        │   Follow     │────────────►│  OrbitFree   │
        │ 镜头跟随角色  │             │ 只转镜头     │
        │              │◄────────────│              │
        └──────┬───────┘  松开左键    └──────────────┘
               │ 按下右键
               ▼
        ┌──────────────┐
        │  OrbitLocked │  镜头与角色朝向联动
        │              │  角色 yaw = 镜头 yaw
        └──────────────┘
```

> **6.5**：只旋转镜头不会改变角色朝向，因此**不能通过看向目标绕过朝向限制**。
> `geometry.test.ts` 里有一条测试专门对照说明这一点。

### 1.4 镜头碰撞（验收 #3）

> 镜头不得穿过墙壁、屋顶、地面、柱子和大型不透明障碍物。
> 角色靠墙时镜头**快速拉近**；离墙后**平滑恢复**原距离。

算法：从角色胸口向镜头理想位置做**球形扫掠**（半径 `CAMERA_PROBE_RADIUS = 0.25 m`），
取最近碰撞点前 `0.1 m` 作为可用距离。

```ts
const ideal = orbitPosition(character.chest, camera.yaw, camera.pitch, targetDistance);
const blocked = sphereCast(character.chest, ideal, CAMERA_PROBE_RADIUS, obstacles);
const allowed = blocked ? blocked.distance - 0.1 : targetDistance;

// ★ 非对称插值：收缩要快（避免穿帮），恢复要慢（避免抽搐）
const k = allowed < currentDistance ? PULL_IN_LERP : RESTORE_LERP;
currentDistance += (allowed - currentDistance) * (1 - Math.exp(-k * dt));
```

| 参数 | 值 | 理由 |
|---|---|---|
| `PULL_IN_LERP` | 40 /s | 几乎瞬时。慢一帧就会穿墙看到墙后的敌人 |
| `RESTORE_LERP` | 6 /s | 平滑恢复。快了会在贴墙走位时反复抽搐 |
| `CAMERA_PROBE_RADIUS` | 0.25 m | 比近裁剪面大，避免墙面在视锥里露出缝隙 |

**这是安全规则，不是画面效果**：镜头穿墙 = 免费的信息优势。

### 1.5 手动拖动期间停止自动跟随（4.3）

> 镜头手动拖动期间，自动跟随必须停止，不能与玩家输入争抢造成摆动。

```ts
if (input.leftDrag || input.rightDrag) {
  autoFollowEnabled = false;
  autoFollowResumeAt = now + AUTO_FOLLOW_DELAY;   // 0.8 s
} else if (now >= autoFollowResumeAt) {
  autoFollowEnabled = true;
}
```

自动跟随指「角色移动时镜头缓慢转到角色背后」。松手后要等 0.8 秒再恢复，
否则玩家刚放开鼠标镜头就自己转走，体验极差。

### 1.6 跳跃时的垂直跟随（4.3）

> 跳跃时镜头垂直跟随**略柔和于**水平跟随，形成重量感，但**不得明显滞后**。

```ts
camera.position.x/z ← 硬跟随（每帧直接对齐）
camera.position.y   ← 指数插值，VERTICAL_LERP = 14 /s
```

14 /s 意味着约 70 ms 追上 63% 的差值 —— 有重量感但不至于让玩家觉得镜头「掉线」。
**落地瞬间要临时提高到 25 /s**，否则从高处落下时镜头会明显拖在角色上方。

### 1.7 第一人称（4.1）

进入第一人称（`distance < FIRST_PERSON_THRESHOLD`）时：

| 隐藏 | 保留 |
|---|---|
| 遮挡视线的头部与躯干（`head` / `torso` 骨骼下的 mesh 设 `visible = false`） | **目标框、技能栏、状态栏** |
| — | **地面范围指示器**（自己的和敌人的） |
| — | 手部与武器（提供动作反馈） |

**不隐藏地面范围是硬要求**（4.1 明确列出），
否则第一人称玩家会看不到脚下的暴风雪边界，构成一个「视角选择带来劣势」的公平问题。

另见 §6：第一人称下要降低近身火焰、烟雾和护盾的透明度（14.3 / 验收 #49）。

### 1.8 死亡观战（4.3 / 11.4）

> 死亡观战只能跟随己方存活玩家，**不能用自由镜头穿墙寻找敌人或潜行目标**。

实现：观战镜头是**受限的第三人称**，锚点必须是某个己方存活玩家，
镜头碰撞规则与活着时完全一致。不提供自由飞行镜头。

配合 [08-network-protocol.md](08-network-protocol.md) 的视野裁剪 ——
观战者收到的快照本身就不含未被发现的敌方潜行者，即使改客户端也看不到。

## 3. 移动物理（规格书 13.5 / 验收 #44、#45）

模拟在 `packages/shared/src/sim/movement.ts`，**客户端和服务器共用**（见 08 §5 预测与回放）。

| 场景 | 要求 | 建议算法 |
|---|---|---|
| **墙体** | 不能穿墙；斜向碰撞时**沿墙滑动**，墙角不高频抖动 | 胶囊体扫掠 → 命中则把速度向量投影到碰撞面切向，最多迭代 3 次（防墙角死循环）；每次迭代后加 `1e-3` 的分离偏移 |
| **低障碍** | 小台阶、路缘和低石块**自动跨越**，不因微小装饰停止 | 水平移动被挡时，把胶囊抬高 `STEP_HEIGHT`(0.45 m) 重试；成功则贴回地面 |
| **坡地** | 缓坡可走；陡坡视为墙或产生下滑，**不能斜向跳爬** | 地面法线与竖直夹角 > `MAX_WALKABLE_SLOPE_DEG`(50°) 视为墙；斜向跳跃落到陡坡上强制下滑 |
| **楼梯/下坡** | **脚部贴地**，不因每级台阶进入跳跃 | 每帧向下探 `STEP_HEIGHT`；探到地面就吸附，并把 `isGrounded` 保持为 true |
| **跳跃** | 保留水平动量，允许**有限**空中修正，不能增加总速度或瞬间反向 | 空中输入只施加 `AIR_CONTROL = 0.25` 的加速度，且**钳制水平速度模长不超过起跳时的值**；不允许速度方向反转超过 90°/s |
| **坠落** | 小落差平滑，大落差有反馈；深水可终止坠落伤害 | 落地时按下落高度分三档：< 3 m 无反馈、3–8 m 屈膝动画、> 8 m 伤害 + 镜头下压 |
| **玩家碰撞** | 玩家、宠物和召唤物**不形成完全实体堵门** | 玩家之间用「软推开」：重叠时互相施加分离速度，但**允许穿过** |
| **位移技能** | 冲锋、闪现、后跃、拉拽都必须停在**合法可站立位置** | 复用 `geometry.clampDisplacement`，撞墙时退回一个身位 |

### 3.1 为什么跳跃要钳制水平速度模长

验收 #45 是「允许有限空中调整但**不能增速或瞬间反向**」。
如果只限制加速度大小而不钳制模长，玩家可以通过在空中反复画圈累积速度（经典 bunny-hop 加速）。
钳制模长后，空中输入只能改变方向、不能提升速度上限。

### 3.2 玩家碰撞为什么是软推开

13.5 明确要求「不形成完全实体堵门」。夺旗战场的基地出口如果能被人肉堵死，
验收 #43「基地出口不会造成永久堵门」就不成立。

软推开的实现：重叠深度 `d` 时，双方各获得 `d * SEPARATION_STRENGTH` 的分离速度，
但**不阻止穿过** —— 一个人可以慢慢挤过一堵人墙，只是会变慢。

## 4. 动画状态机（规格书 13.3 / 13.4）

### 4.1 必须覆盖的动作（13.3）

| 类别 | 动作 |
|---|---|
| 移动 | 站立、战斗待机、前进、奔跑、后退、左右侧移、跳跃、下落、落地、游泳 |
| 受击 | 受击、死亡 |
| 武器 | 单手、双手、双持、盾击、弓、弩、法杖、魔杖 |
| 施法 | 施法、引导、冲锋、旋转攻击 |
| 状态 | 昏迷、恐惧、定身、变形、潜行、完全免疫、护盾、复活、旗手 |

### 4.2 状态转移

```
                    ┌─────────┐
          ┌────────►│  Idle   │◄────────┐
          │         └────┬────┘         │
   速度<阈值下限          │ 速度>阈值上限  │ 速度<阈值下限
          │              ▼              │
     ┌────┴────┐   ┌──────────┐   ┌────┴─────┐
     │  Walk   │◄─►│   Run    │◄─►│  Strafe  │
     └────┬────┘   └────┬─────┘   └──────────┘
          │             │
          │  Space      │
          ▼             ▼
     ┌─────────┐   ┌─────────┐   ┌─────────┐
     │  Jump   │──►│  Fall   │──►│  Land   │──► 回到移动状态
     └─────────┘   └─────────┘   └─────────┘

  任意状态 ──受击──► Hit（叠加层，不中断下半身）
  任意状态 ──控制──► Stunned / Feared / Rooted / Polymorphed（全身覆盖）
  任意状态 ──死亡──► Death（终态）
```

上半身与下半身**分层**：施法、受击只影响上半身，
角色可以一边跑一边播放受击 —— 否则被持续伤害打中会导致跑步动画不停被打断。

### 4.3 稳定性（13.4 / 验收 #47）

> 移动状态具有速度平滑和**进入/退出迟滞**，不能因单帧位置抖动反复切换待机和奔跑。

**迟滞（hysteresis）是关键**。用两个不同的阈值，不是一个：

```ts
const SPEED_ENTER_RUN = 2.0;   // 速度超过 2.0 才进入 Run
const SPEED_EXIT_RUN  = 1.2;   // 速度低于 1.2 才退出 Run
```

单阈值会在速度恰好在阈值附近抖动时产生每帧切换的闪烁。

再加一层速度平滑：`smoothedSpeed += (rawSpeed - smoothedSpeed) * (1 - exp(-8 * dt))`，
状态判定用 `smoothedSpeed` 而不是原始值。

| 要求（13.4） | 实现 |
|---|---|
| 传送、位置纠正和大位移**不能被识别为高速跑步** | 位移超过 `TELEPORT_THRESHOLD`(3 m/帧) 时**不更新** `smoothedSpeed`，直接瞬移并保持当前动画状态 |
| 腿部动作节奏与实际速度一致，减速后不得高速摆腿滑行 | 移动动画的 `timeScale = smoothedSpeed / ANIM_REFERENCE_SPEED`，不是固定 1.0 |
| 缺失专属动作时使用最接近的武器动作，**不能显示 T 形姿态** | 动画注册表按 `handedness` 做回退链：`dualWield → oneHand → default`；查不到时**保持上一个有效动作**，绝不落到 T-pose |

## 5. 武器挂点与装备表现（规格书 13.6）

| 规则 | 实现 |
|---|---|
| 主手、副手、盾牌、双持和双手武器连接正确骨骼挂点 | 挂点表 `Record<WeaponHandedness, BoneName[]>`，模型按 `WeaponDef.model` 键从注册表取 |
| **只显示正在使用的主要武器**，备用装备存于状态栏，不把所有武器堆在背部 | 场上任一时刻最多两个武器 mesh（主手 + 副手/盾） |
| 武器收起和取出必须有过渡；切换后模型、挂点和攻击动作**同步改变** | 换装 0.8 秒（`EQUIP.SWAP_WEAPON_SECONDS`）内播放收起→取出，**动画结束帧**才替换 mesh 与攻击动作集（验收 #35） |
| 德鲁伊动物形态**隐藏人形武器**；装备效果仍按当前方案生效 | 形态切换时武器 mesh `visible = false`，但 `WeaponDef.modifiers` 继续参与数值计算 |
| 护甲切换可改变胸甲、肩部、披风和材质，但**不能改变角色碰撞体或职业识别** | 护甲只换材质与附属 mesh，**碰撞体永远是 `GEOMETRY.HITBOX_RADIUS/HEIGHT` 常量**（验收 #10） |

**阵营区分**（13.2）：通过姓名板、脚下标记、轮廓和 UI 区分，
**不把整个人物简单染红或染蓝** —— 那会破坏职业通过颜色识别的能力。

## 6. 特效与战斗可读性（规格书 14.x）

### 6.1 技能表现六阶段（14.1）

| 阶段 | 内容 | 何时可省略 |
|---|---|---|
| 预备 | 手部、武器、符文或身体积蓄能量 | 低画质可简化，不可完全省略（是施法的视觉预告） |
| 释放 | 明确闪光、动作和声音 | 不可省略 |
| 飞行 | 投射物主体、方向和轨迹 | **主体不可省略**，拖尾可省略 |
| 命中 | 伤害、治疗、格挡、闪避、免疫或驱散反馈 | 不可省略 |
| 持续 | 地面区域、护盾、光环和控制附着 | **边界不可省略**，装饰粒子可省略 |
| 结束 | 淡出、破碎、熄灭或消散 | 可简化 |

### 6.2 八属性视觉语言（14.2）

| 属性 | 颜色 | 形状与运动 |
|---|---|---|
| 火焰 | 橙红、亮黄 | 火舌、余烬、热浪、焦痕 |
| 寒冰 | 浅蓝、冰白 | 冰晶、霜雾、雪花、冻结底座 |
| 奥术 | 紫、蓝紫 | 符文、几何轨迹、空间波纹 |
| 暗影 | 深紫、黑红 | 烟雾、扭曲、灵魂丝线 |
| 神圣 | 暖金、象牙白 | 光柱、圆形符文、护盾 |
| 自然 | 绿、青绿、月白 | 叶片、藤蔓、水波、月光 |
| 物理 | 暖白、钢铁、土黄 | 刀光、火花、尘土、冲击线 |
| 毒素 | 黄绿、暗绿 | 液滴、细雾、刀刃附着 |

**颜色不是唯一区分手段**（17.2 可访问性）：每个学派同时有独立的形状语言，
色盲模式下靠形状仍能分辨。

### 6.3 关键可读性规则（14.3）

- 地面危险区域的**真实边界**在整个有效期内持续显示；装饰粒子可以淡出，**边界不能消失**
- 环形技能必须**同时**显示内圈和外圈
- 延迟技能显示**落点和倒计时**（陨石的唯一反制方式就是看到落点走开）
- 定身**附着脚部**，昏迷显示**头顶标记**，沉默与恐惧使用**不同**视觉，避免混淆
- 护盾需要**激活 / 承伤 / 强度衰减 / 破裂**四种不同反馈
- 第一人称降低近身火焰、烟雾和护盾的透明度，**不能遮满屏幕**
- 最远镜头保留**旗手、姓名板、投射物主体、地面边界**，减少装饰粒子

### 6.4 低画质公平（14.4 / 验收 #48）

这是两张**对照清单**，不是建议：

| ✅ 低画质**可以**减少 | ❌ 低画质**绝对不能**隐藏 |
|---|---|
| 余烬、火星 | 角色 |
| 雪花、霜屑 | 目标 |
| 环境叶片、草动 | **旗手** |
| 武器装饰光点 | **投射物主体** |
| 非关键光照、阴影分辨率 | **地面真实边界** |
| 拖尾长度、粒子数量 | **控制状态**（昏迷/定身/沉默/恐惧标记） |
| 屏幕后处理（泛光、景深） | **完全免疫** |
| 布料/头发物理 | **复活保护** |

### 6.5 画质档位

| 效果 | 高 | 中 | 低 |
|---|---|---|---|
| 阴影 | 级联 4 级 | 2 级 | 关 |
| 粒子数量 | 100% | 50% | 20% |
| 拖尾 | 开 | 短 | 关 |
| 泛光 / 景深 | 开 | 泛光 | 关 |
| 环境细节（草、叶） | 开 | 稀疏 | 关 |
| 布料 / 头发物理 | 开 | 关 | 关 |
| **地面区域边界** | **开** | **开** | **开** |
| **控制状态标记** | **开** | **开** | **开** |
| **投射物主体** | **开** | **开** | **开** |
| **旗手标记与姓名板** | **开** | **开** | **开** |
| **护盾四态反馈** | **开** | **开** | **开**（简化为纯色描边） |

**论证低画质不产生竞技优势**：
表格下半部分（加粗行）在三档中完全一致 —— 这些是**做决策所需的全部信息**。
上半部分是纯装饰。因此低画质玩家看到的信息集合与高画质**完全相同**，
只是好看程度不同。反过来也成立：高画质的粒子不会遮挡关键信息，
因为关键信息统一渲染在装饰粒子**之上**的图层。

### 6.6 可访问性（17.2）

- 全部按键可重绑（见 §2）
- 色盲模式：改变学派配色为色盲友好方案，形状语言不变
- 危险区域**不能只依赖颜色**：配合边框、形状、动画和声音
- 界面缩放、减弱镜头震动、降低特效强度
- 伤害数字、屏幕闪烁、武器粒子和姓名板密度**可单独调整**

## 7. 实现顺序建议（M1）

1. `shared/sim/movement.ts` + `movement.test.ts` —— 纯逻辑先行，可单测
2. `shared/data/maps/testbed.ts` —— 墙、柱、楼梯、缓坡、陡坡、低栏杆各一
