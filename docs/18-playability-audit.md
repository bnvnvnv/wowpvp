# 可玩性审查与本轮改动

日期：2026-09-05。范围：伤害归属、正式比赛入口、淘汰与复活、夺旗战资源经济、
人机目标行为、大厅美术与选择流程。

## 发现与修复

| 问题 | 代码原因 | 本轮结果 |
|---|---|---|
| 无法区分自己的输出 | `HitFeedback.onHit` 对所有可见伤害使用同一套浮字，其他人的暴击也会放大 | 默认仅显示自己的输出与受伤；受伤为红色负数。设置可打开其他人的小号标记数字 |
| 3v3 看起来没有输赢 | 此前试玩入口是 `CombatDirector.reviveInTestbed`，死亡后立即复活；大厅未明确区分训练与正式比赛 | 训练场标注无限复活、不计胜负；正式竞技场提供独立的快速入口，使用服务器淘汰规则 |
| 潜行会让存活人数变化 | `NetworkScene.renderModeHud` 按可见实体计数 | 快照下发服务器存活总数，不下发隐藏玩家的位置或身份详情 |
| 夺旗没有成长循环 | 商店、积分、随机道具主要装配在 FFA；CTF 没有经济状态 | 新增单局战场经验、基地商店；BOSS 与随机补给在夺旗默认生效 |
| BOSS 有时没有战利品 | 掉落受 `arsenal.enabled` 控制，经典预设原本关闭它 | 夺旗启用掉落仓，沿用既有拾取、备用装备和道具规则 |
| 人机不参与夺旗 | `BotDriver.tick` 原先只选敌人并调用战斗 AI | 新增拔旗、护送、回防、归还、交旗目标，使用 PathFinding.js A* 绕过地图障碍 |
| 道具显示未知物品 | 快照只查武器与护甲名称，没有查消耗品目录 | 消耗品显示具体名称 |
| 首页缺乏游戏画面 | 原大厅使用大图标与 CSS 背景，没有实机图 | 四张实机截图、八张角色图、独立模式卡与带武器的角色预览 |
| 联网画布只占部分窗口 | `#match-root` 未指定高度，内部百分比高度无法按整个窗口计算 | 联网容器固定到整个视口，修复桌面和窄屏的黑色空白区 |
| 选人页顶部按钮不可达 | 高内容容器仍纵向居中，顶部落入无法回滚的负空间 | 页面对齐顶部并允许正常滚动 |
| 新手不知道该往哪里去 | 小地图原先只显示旗手和掉落旗，不显示基地旗点及商店 | 增加旗点、BOSS、补给与己方商店标记；远处主要目标保留边缘方向 |

主要实现位置：

- `packages/client/src/feedback/HitFeedback.ts`

## 当前玩法

| 入口 | 规模 | 胜负 | 阵亡 |
|---|---|---|---|
| 团队竞技场 | 1v1 至 5v5 | 单回合，全队被淘汰判负；同时全灭按既有窗口判平局 | 本回合不复活，可观战队友 |
| 夺旗战场 | 6v6、8v8、12v12 | 默认先夺 3 旗；保留时限、加时和原有交旗条件 | 按波次复活，保留复活保护 |
| 大乱斗 | 沿用既有人数配置 | 击杀达到目标获胜，HUD 显示目标和领先者 | 按既有规则复活 |
| 训练场 | 本地训练 | 不计胜负 | 无限复活，界面明确标注 |

快速入口复用真实房间、职业选择和准备协议，自动启用人机补位。
好友仍可创建、分享、加入房间；已有的大人数竞技场协议值保留兼容，默认界面推荐
小队竞技场与大型夺旗两类团队玩法。

## 夺旗经验

经验是单局可消费余额；阵亡保留余额，新比赛归零。另记本局累计获得量，购买不会
降低累计量。服务器决定奖励、价格与购买结果，客户端只提交商品编号。

| 来源 | 奖励 |
|---|---|
| 敌方玩家击杀 | 90 |
| 最近 12 秒内的伤害助攻或相关治疗支援 | 45，每次击杀按贡献者去重 |
| 归还己方旗帜 | 60 |
| 成功夺旗 | 全队每人 120，旗手额外 60 |
| 击杀 BOSS | 击杀方全队每人 180 |

商店出售本职业的备用武器（240）、备用护甲（180）及既有三类消耗品（60）。
购买需要存活、位于己方基地且未携旗；余额不足、栏位已满和重复提交会被拒绝。
武器进入备用栏，装备切换仍按原有规则完成；临时物品仍受既有死亡清理规则约束。

BOSS 首次 60 秒出现，击杀后 105 秒刷新；战利品按实际职业池产生。
随机补给沿用既有定时与数量预算，在检查过支撑面、净空和对称性的落点产生。
以上经验和价格是可玩的初版，尚未完成多人职业组合的长期配平。

## 仍需投入

| 优先级 | 不足 | 依据与下一步 |
|---|---|---|
| P1 | 地图仍有大量重复石墙与开阔铺地 | `data/maps/ctf.ts` 的主体仍是几何体。补给增加了争夺目标，但没有完成整张地图的美术重制；下一步应做中央 BOSS 区、两翼路线与基地各自的地标和材质 |
| P1 | 职业动作与技能辨识度仍不够 | `CharacterView` 复用现成动画，`SpellVfx` 仍主要按元素与形态共用表现。应优先逐招制作各职业 3 个核心技能的动作、声音、轨迹和落点表现 |
| P1 | 新经济与目标 AI 需要对局配平 | `BattleObjectives` 是基础分工，尚不是高水平团队策略；经验奖励尚无长局样本。重点测旗手存活时间、首夺旗时间、BOSS 参与率、双方经验差和平均对局时长 |
| P1 | 玩家在障碍拐角的体验还需专门处理 | `movement.ts` 仍采用既有贴墙解算；此前 `docs/17-game-feel-roadmap.md` 已记录拐角吸附。新 A* 只改善夺旗人机的路线，不替代玩家移动物理修复 |
| P2 | 快速开始还不是匹配队列 | `LobbyShell.startQuick` 创建房间并用人机补位；没有按水平寻找真人对手。后续需要跨房间匹配、队伍组队和排队状态 |
| P2 | 多局赛制没有完整的服务器回合切换 | `RoomConfig.roundsToWin` 与 shared 回合状态存在，但 `MatchLoop.checkEnd` 当前读取单次回合结果即结束比赛。当前界面明确提供单回合竞技；三局两胜应作为独立规则补齐后再开放 |
| P2 | 新增战场玩法缺少独立互动教学 | 现有教学主要覆盖移动和基础战斗；大厅与 HUD 已给出模式规则和目标，但尚未增加完整的拔旗、交旗、补给、购买教学关 |
| P2 | 运营与留存仍是后续模块 | 当前入口围绕房间和本地昵称运行。账号、生涯、段位、战绩持久化与回放不在本轮实现范围内 |

先把 3v3 与 6v6 做成持续可测的两种核心体验，再按实战结果扩展内容。

## 验证

- 全量回归：139 个文件、2915 项测试通过。
- 新增完整链路测试覆盖 1v1 至 5v5 的死亡淘汰和判胜、夺旗经验入账与私信、
  购买与余额同步、波次复活、BOSS 战利品，以及人机实际跑图拔旗并交旗。
- 类型检查与 ESLint 通过。
- 全项目生产构建通过；仍有原有的运行时字体/光标路径与大 chunk 提示。
- 浏览器实际走通竞技场、夺旗战、大乱斗入口与角色选择；捕获商店与 BOSS 刷新。
- 最终布局复验：1440×900 与 390×844 的联网画布 CSS 尺寸均等于视口，
  两个视口各 81 个 WebGL 像素样本均非黑，无图片请求错误或脚本异常，选人返回按钮可用。
- 后续地图素材与大厅变更的定向回归 173 项通过；修复了夺旗装饰中不存在的补给箱路径。
- 诊断截图与报告保留在 `scripts/.diag/playability-20260905/`，该目录不入库。
- 本机已有 8080 服务未停止；本轮更新后的服务运行在 8081。客户端的本地
  `.env.development.local` 设置 `VITE_GAME_PORT=8081`，该文件不入库；默认发布端口仍为 8080。

## Blender 制作建议

推荐用 Blender 制作和迭代模型、武器、地图地标与专属动画，再导出 GLB 接入
现有 `ModelLibrary`。当前加载器已经支持 glTF 蒙皮和动画，不需要为引入 Blender
更换 Three.js 渲染引擎。

第一批优先做战士重击与法师冰火核心技能的动作，以及夺旗战中央 BOSS 区和基地。
保留或明确映射骨骼、左右武器挂点与动作片段名称；程序化材质需转成网页端可用的
贴图和材质。飞行轨迹、连续拖尾、命中判定与性能预算继续由游戏运行时代码负责。

Blender 是制作工具，完成度仍取决于具体的造型、配色、动画节奏与实机迭代。
